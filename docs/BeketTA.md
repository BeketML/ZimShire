Good luck zimran   Intro   Warren Buffett has spent nearly 50 years sharing his investment philosophy through annual shareholder letters some of the most studied, quoted, and respected texts in finance.   Problem   Yet most investors have never read them in full, and no tool exists to research companies the way Buffett would.   Solution   To change this, your assignment is to build ZimShire a public-facing AI investment research assistant that helps investors research any public company through a Buffett-first lens. ZimShire combines Buffett's timeless philosophy, live market data, and real-time web search to answer questions that neither a search engine nor a generic chatbot can:   "How would Buffett evaluate Apple's moat based on his letters?"   "What does NVIDIA's current P/E ratio say about its margin of safety?"   "Is Coca-Cola still the kind of business Buffett described in 1988?"   ZimShire is not a stock screener, a prediction engine, or a financial advisor. It is a research companion - grounding every answer in primary sources and live data.   Task 1 - Core Service   Build a provider-agnostic chat API using FastAPI (async) that serves as the single entry point for all user interactions. The service must support:   Selecting any model and provider at runtime (OpenAI, Anthropic, etc.).   Streaming responses - tokens must be delivered progressively as they are generated.   Conversation history persistence across turns, stored in a database.   All LLM calls must be fully async.   Task 2 – RAG Pipeline   Build a production-quality retrieval pipeline over the indexed Buffett letters corpus. Index the corpus once before submission - the pipeline does not need to support re-ingestion at runtime. Every response grounded in the letters must include source attribution (letter year + relevant passage). If an answer cannot be grounded in the retrieved context, the response must return "grounded": false not a plausible-sounding hallucination. Document your chunking strategy, retrieval design, and any tradeoffs in the README.   Task 3 – Multi-Agent Research System   Build ZimShire's intelligence as a multi-agent system using LangGraph. The system must integrate all three data sources the Buffett letters via RAG, live market data via yfinance, and current web search - into a coherent, stateful research experience. The architecture, agent breakdown, and orchestration patterns are entirely your design decision. Conversation state must be persisted via LangGraph checkpointing to support coherent multi-turn sessions - e.g., "Now compare that to what he said about banks in 1990."   Task 4 - MCP Server   Expose ZimShire's capabilities as a standalone MCP server using FastMCP, consumable by any MCP-compatible client (ClaudeCode, Cursor, custom agents). What tools, resources, and prompts to expose is your design decision.  The server must run independently of the main FastAPI app. All tools must have fully typed signatures and precise docstrings.   Task 5 - Observability   Instrument the full system with Langfuse. Every user query must produce a session with traces spanning the full request lifecycle - from routing and retrieval through to the final response - capturing latency, token usage, and cost at every LLM call.   Task 6 - Guardrails   Input guardrail: Queries asking for unrelated themes or prompt-injections must be blocked and redirected with a clear, user-friendly message. Output guardrail: Any response containing direct buy/sell recommendations, explicit price targets, or personalized portfolio advice must be rewritten or replaced never returned as-is. Faithfulness guardrail: All responses grounded in the Buffett letters must be attributable to retrieved passages. Document your design and its tradeoffs in the README.   Optional Bonus Task   Semantic Caching: Cache semantically similar queries above a similarity threshold to avoid redundant LLM calls.   Long-Term User Memory: Agent remembers users' tracked companies and research interests across sessions to personalize future responses.
